### Key Implementation Decision — P2-07 (Ed25519/ECDSA Keys)

Paramiko 4.x dropped `Ed25519Key.generate()` and `ECDSAKey.generate()`. The
fix generates keys via the `cryptography` library directly, serialises to
OpenSSH PEM format, then loads back into Paramiko via `from_private_key()`.

This approach was chosen because it avoids a Paramiko version pin and keeps the
key format standard. The significant downside — discovered only in Session 2 —
is described below.

## Session 2 — Post-Implementation Bug Scan

Reviewed all 13 files modified in the two security-fix commits. Found 10 bugs —
some introduced by the fixes, others pre-existing but now more visible after the
surrounding code changed.

### Critical Finding — P2-07 Key Generation Crash

The most significant discovery: the P2-07 Ed25519/ECDSA key generation fix
crashes the backend on every fresh startup.

**What happens:** `_generate_ed25519_key()` and `_generate_ecdsa_key()` generate
a key via the `cryptography` library and wrap it in a Paramiko key object using
`from_private_key()`. The code then calls `.write_private_key_file()` on the
result. Paramiko does not implement this method on keys loaded via
`from_private_key()` — it falls through to `PKey.write_private_key_file()` which
raises `Exception("Not implemented in PKey")`.

**Impact:** Container enters a crash-restart loop immediately on any install
without pre-existing key files. RSA is unaffected because `RSAKey.generate()`
still works in Paramiko 4.x and its generated objects do implement the write
method. Ed25519 and ECDSA crash.

**Fix (documented, not yet applied):** Separate generation from saving —
write the raw PEM bytes directly to disk with `path.write_bytes()`, then load
back with `from_private_key_file()`. Full details in BUG-01 in
`docs/security/security-bugs.md`.
