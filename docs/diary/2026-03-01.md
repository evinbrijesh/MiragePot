## Key Decisions

### MVP document vs PRD — why both?

These documents serve different purposes:

- The **MVP document** is scoped to execution — what was built, why each decision was made, how it works, how it was tested. It answers the question: *"Did you build the right thing, and did you build it correctly?"*
- The **PRD** is scoped to requirements — what the system must do, for whom, under what constraints, measured against what criteria. It answers the question: *"What are you building and why?"*

For an academic submission they complement each other well. The PRD frames the problem and the requirements; the MVP document demonstrates delivery against those requirements.

### Why rewrite the PRD rather than patch it?

The original PRD (v1.0) was structurally sound but lacked the rigour expected in a formal document: no acceptance criteria, no non-goals, no constraints, no glossary, and shallow persona descriptions. Rather than appending these piecemeal and creating an inconsistent document, it was cleaner to rewrite with consistent formatting, IDs, and section structure throughout.

## Session 2 — Phase 1 Security Hardening (Post-Audit Fixes)

After the documentation session, a second session was run to complete Phase 1 security hardening. A post-Phase-1 audit had identified 2 critical and 5 high severity issues that were not addressed in the initial hardening pass. All 7 were fixed in this session.

### Issues Fixed

| ID | Severity | File | Issue |
|---|---|---|---|
| CRITICAL-1 | Critical | `.env.docker` | `GRAFANA_ADMIN_PASSWORD=admin` — default weak password replaced with strong value and warning comment |
| CRITICAL-2 | Critical | `docker-compose-simple.yml` | No security hardening — added `cap_drop: ALL`, `cap_add: NET_BIND_SERVICE`, `security_opt: no-new-privileges:true`, and resource limits to both services |
| HIGH-1 | High | `miragepot/ai_interface.py` | `temperature=0.7` and `num_predict=512` hardcoded — replaced with `cfg.temperature` and `cfg.max_tokens` from `get_config().llm`; `timeout` parameter was accepted but ignored — now enforced via `ThreadPoolExecutor.result(timeout=cfg.timeout)` |
| HIGH-2 | High | `docker/docker-compose.yml` + `docker-compose-simple.yml` | Dashboard, metrics, Alertmanager, and Grafana ports bound to `0.0.0.0` — prefixed all non-SSH port bindings with `127.0.0.1:` (5 ports across both files) |
| HIGH-3 | High | `docker/Dockerfile` | `COPY data/ ./data/` baked `host.key` and logs into the image at build time — replaced with two explicit copies of only `system_prompt.txt` and `cache.json` |
| HIGH-4 | High | `miragepot/command_handler.py` | `except Exception: pass` inside `_is_suspicious_unicode()` security function — fail-open behaviour; replaced with fail-closed: logs a warning and returns `True` (suspicious); also added `import logging` and `LOGGER = logging.getLogger(__name__)` which were missing from the module |
| HIGH-5 | High | `.gitignore` | No explicit entry for `.env.docker` — added as belt-and-suspenders alongside the existing `.env.*` pattern |

### Key Technical Decisions

**HIGH-1 (timeout enforcement):** The `timeout` parameter on `query_llm()` was documented in the function signature and docstring but was never actually passed to the Ollama client. The Ollama Python library does not expose a direct timeout parameter on `ollama.chat()`, so the fix wraps the call in a `concurrent.futures.ThreadPoolExecutor` and calls `future.result(timeout=cfg.timeout)`. This gives hard timeout enforcement without changing the call signature.

**HIGH-4 (fail-closed):** Security detection functions should never silently swallow exceptions and return `False`. If the Unicode injection check fails for any reason (malformed input, encoding error, etc.), the safe default is to treat the input as suspicious and block it. The cost of a false positive is a rejected command; the cost of a false negative is a prompt injection reaching the LLM.

**HIGH-3 (Dockerfile COPY):** `host.key` is auto-generated at startup by `get_or_create_host_key()` in `server.py` and must not be baked into the image — any image published to a registry would expose the private key to anyone who pulls it. Logs are provided exclusively via volume mount.

### Findings and fixes

**14 mypy errors → 0 errors**

| File | Line(s) | Error | Fix |
|---|---|---|---|
| `miragepot/ssh_interface.py` | 158, 159, 179, 202 | `no-any-return` + `attr-defined` on `paramiko.OPEN_SUCCEEDED` etc — `types-paramiko` stubs don't re-export these constants at the top-level `paramiko` namespace | Imported constants directly from `paramiko.common` (`OPEN_SUCCEEDED`, `OPEN_FAILED_ADMINISTRATIVELY_PROHIBITED`, `AUTH_SUCCESSFUL`, `AUTH_FAILED`); removed `paramiko.` prefix from all four return statements |
| `miragepot/server.py` | 97, 111 | `"str" has no attribute .get"` and `arg-type` on `sessions.append()` — `json.loads()` returns `Any`, mypy couldn't narrow the type | Added explicit `Dict[str, Any]` annotation on `live_data`; added `cast(List[Dict[str, Any]], ...)` on `sessions` and `cast(str, ...)` on `session_id`; added `List` and `cast` to typing imports |
| `miragepot/response_validator.py` | 452 | `no-any-return` — dict lookup on `fallbacks` returns `Any` | `cast(str, fallbacks[base_cmd])` |
| `miragepot/ai_interface.py` | 447 | `no-any-return` — LLM response content extracted via chained `.get()` returns `Any` | `cast(str, response.get("message", {}).get("content", ""))` with explicit `content: str` annotation |
| `miragepot/command_handler.py` | 460, 1562, 2489 | `no-any-return` — `json.loads()`, `dict.get()`, and dict subscript all return `Any` | `cast(Dict[str, str], json.loads(...))` in `_load_cache()`; `cast(str, state.get("cwd", ...))` in `_handle_pwd()`; `cast(str, files[filepath])` in pager handler |
| `miragepot/__main__.py` | 445 | `no-any-return` — `args.func(args)` dispatch returns `Any` | `cast(int, args.func(args))` |

**Note on `server.py:97/111`:** These looked like real runtime bugs from the mypy output (`"str" has no attribute .get"`), but investigation confirmed they are annotation-only issues — `json.loads()` returns `Any` so mypy loses the dict type. The code was correct at runtime; the fix makes the types explicit so mypy can verify them statically.

**`types-paramiko` stub added**

`types-paramiko>=3.0.0` added to `requirements.txt`. Without this, mypy cannot type-check any Paramiko call site — the SSH server core would be invisible to static analysis. This is a prerequisite for a clean CI/CD mypy step.

**`data/logs/.gitkeep` staged**

The `data/logs/` directory was showing as untracked in `git status`. The `.gitkeep` file was present on disk but had never been committed. Staged and included in this commit.
