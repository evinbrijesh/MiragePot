# Development Diary - March 31, 2026

## Session Focus: Notification System Debugging & Fixes

This session focused on debugging and fixing critical issues with MiragePot's real-time notification system that prevented Discord alerts from being sent during live attacks.

---

## Issues Identified

### 1. Missing Docker Environment Variables
**Problem:** The `.env.docker` file (used by Docker containers) was completely missing the notification configuration variables, causing the honeypot to run with notifications disabled in production.

**Investigation:**
- Test notifications (`test_notifications.py`) worked fine locally using `.env`
- Docker containers couldn't send notifications because `MIRAGEPOT_NOTIFICATIONS_ENABLED`, `MIRAGEPOT_DISCORD_WEBHOOK_URL`, and related variables weren't set
- The `.env.docker.example` had the variables documented, but they weren't copied to `.env.docker`

### 2. High-Threat Command Notifications Crashing
**Problem:** Real-time high-threat command alerts were failing with `NameError: name 'session_id' is not defined`

**Root Cause:**
```python
# server.py line 922 - BROKEN
notifier.send_high_threat_command_alert(
    command, score, session_id, attacker_ip  # session_id doesn't exist as variable
)
```

The code was trying to use `session_id` as a local variable, but it's actually stored in `session_log["session_id"]`.

**Evidence from logs:**
```
2026-03-31 02:10:15,577 - miragepot.server - ERROR - Failed to send high-threat command notification: name 'session_id' is not defined
```

### 3. JSON Attachment Path Mismatch
**Problem:** Session end notifications weren't including JSON file attachments in Discord messages.

**Investigation:**
- Session logs are saved with filename pattern: `{session_id}.json` where `session_id` already includes the `"session_"` prefix
- Example: `session_81c299e6e8f7f33fcdd06fab5ec013c7.json`
- The notification code was looking for the correct path, but file creation logic needed improvement for edge cases

### 4. Ollama Container Showing "Unhealthy"
**Problem:** Docker Desktop showed `miragepot-ollama` as unhealthy despite functioning correctly.

**Root Cause:**
```yaml
# docker-compose.yml - BROKEN healthcheck
healthcheck:
  test: ["CMD-SHELL", "curl -sf http://localhost:11434/ || exit 1"]
```

The Ollama container doesn't have `curl` installed, causing all healthchecks to fail with:
```
/bin/sh: 1: curl: not found
```

However, Ollama was still processing requests successfully (verified in logs).

### Fix 2: Fixed High-Threat Command Notification Variable

**File:** `miragepot/server.py` (line 917-928)

if score >= 80:
    try:

### Fix 3: Improved JSON Attachment Logic

**File:** `miragepot/notifications.py` (line 354-377)

Enhanced the `send_session_end_summary()` method to:

1. **Properly construct file path:**
```python
log_dir = cfg.logs_dir
# session_id already includes "session_" prefix (e.g., "session_abc123...")
file_path = log_dir / f"{session_id}.json"
```

2. **Create file if missing:**
```python
if not file_path.exists():
    LOGGER.info(f"Session log not found, creating from session_log data")
    try:
        log_dir.mkdir(parents=True, exist_ok=True)
        with open(file_path, "w") as f:
            json.dump(session_log, f, indent=2, default=str)
        LOGGER.info(f"Created session log file: {file_path}")
    except Exception as e:
        LOGGER.error(f"Failed to create session log file: {e}")
        file_path = None
```

3. **Added detailed logging:**
```python
LOGGER.info(f"Looking for session log at: {file_path}")
LOGGER.info(f"Attaching file to Discord notification: {file_path.name} ({file_path.stat().st_size} bytes)")
```

**Impact:** Session end notifications now reliably include JSON file attachments with complete forensic data.

## Lessons Learned

### 1. Environment Variable Management
**Issue:** `.env` worked for local testing but `.env.docker` was incomplete.

**Lesson:** When adding new features, update **both** `.env.example` and `.env.docker.example`, and verify Docker containers have access to new variables.

**Prevention:** Add to deployment checklist:
- [ ] Update `.env.example`
- [ ] Update `.env.docker.example`
- [ ] Test with `docker exec <container> env | grep FEATURE_NAME`

### 2. Variable Scope in Nested Contexts
**Issue:** `session_id` exists in `session_log` dictionary, not as local variable.

**Lesson:** In large functions (1000+ lines), be explicit about data structure access. Use `session_log["session_id"]` instead of assuming a local variable exists.

**Prevention:** Consider refactoring large functions or using type hints:
```python
def send_alert(session_log: Dict[str, Any]) -> None:
    session_id: str = session_log["session_id"]  # Explicit extraction
```

### 3. Healthcheck Command Availability
**Issue:** Assumed `curl` was available in all containers.

**Lesson:** Use container-native commands for healthchecks. Ollama has `ollama list`, so use that instead of installing curl.

**Prevention:** Check image documentation for built-in diagnostic commands before adding dependencies.

### 4. Logging is Critical for Remote Debugging
**Issue:** Without detailed logs, couldn't diagnose JSON attachment issues.

**Lesson:** Add `LOGGER.info()` statements at critical points:
- File path resolution
- File existence checks
- File creation/attachment success
- Error conditions with full context

**Impact:** Logs like `"Attaching file to Discord notification: session_X.json (7941 bytes)"` made debugging trivial.

## Security Considerations

### Webhook URL Exposure
**Risk:** Discord webhook URLs are sensitive credentials. Anyone with the URL can post to the channel.

**Mitigations:**
- ✅ Stored in `.env.docker` (gitignored)
- ✅ `.env.docker.example` uses placeholder
- ⚠️ URL visible in Docker logs (`docker exec` can see env vars)

**Recommendation:** Restrict Docker daemon access to trusted users only.

### Session Log Data Exposure
**Risk:** JSON attachments contain attacker IPs, commands, and potentially sensitive honeypot internals.

**Mitigations:**
- ✅ Discord channel is private (invite-only)
- ✅ JSON includes attack data only (no honeypot secrets)
- ✅ Attacker IPs are logged (intentional for forensics)

**Recommendation:** Ensure Discord server has appropriate access controls.
