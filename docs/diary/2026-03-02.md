## Session 1 — Deployment Hardening: Docker Pre-flight Checks in `start.sh`

Identified and fixed a usability gap: running `./start.sh` on a fresh system (new laptop or cloud VM) with no Docker installed would fail immediately with a cryptic shell error, giving no guidance on what to do.

### Problem

`start.sh` called `docker compose ...` as its first real operation with no guard. Any system without Docker installed — including all fresh cloud VMs (EC2, GCP, DigitalOcean, etc.) — would hit an unhandled error. The script gave no actionable output.

### Fix — `start.sh`

Added two pre-flight checks at the top of `start.sh`, before any Docker calls:

**1. Docker check (lines 15–66)**

- Detects if `docker` is missing from `$PATH`
- **Linux:** Prompts `Install Docker now? [y/N]`
  - If yes: downloads `https://get.docker.com` to `/tmp/get-docker.sh`, runs it, then adds the current user to the `docker` group. If the download fails (dead URL, no internet), falls back gracefully to printing manual install instructions — the script never crashes from a failed curl.
  - If no: prints `https://docs.docker.com/engine/install/` and exits cleanly
- **macOS:** Points to Docker Desktop (`https://docs.docker.com/desktop/install/mac-install/`) and exits
- **Other platforms:** Generic install URL and exit

**2. Docker Compose check (lines 68–76)**

- Separately verifies `docker compose version` works (v2 plugin)
- Catches cases where Docker is installed but is too old to have the Compose plugin bundled
- Exits with a clear message pointing to the install/update docs

### Key Design Decisions

**Why `get.docker.com` for Linux auto-install?**
It's the official Docker convenience script, maintained by Docker Inc., and works across all major Linux distros (Debian, Ubuntu, CentOS, RHEL, Fedora, Arch) by detecting the distro internally and using the correct package manager. This is exactly what cloud VMs run.

**Why prompt before installing rather than auto-installing silently?**
Running a `curl | sh` from the internet without user consent is bad practice — even from an official source. The prompt makes the action explicit and transparent.

**Why wrap the curl in an `if` block rather than letting `set -e` handle failure?**
`set -euo pipefail` would abort the entire script if `curl` fails (e.g. no internet, URL changes). Wrapping in `if curl ...; then ... else ... fi` means a failed download degrades gracefully to a printed fallback message instead of a confusing crash.

**Why a separate Compose check?**
Docker and Docker Compose are separate failure modes. Someone could have Docker CE installed from years ago (pre-v20.10) without the Compose v2 plugin. A single `command -v docker` check would pass but `docker compose` would still fail. The second check catches this case explicitly.
