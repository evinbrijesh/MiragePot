### Bug #1 — Metrics Server Not Started (Critical) ✓

`start_metrics_server(port=9090, host="0.0.0.0")` is called in `run_server()` in
`__main__.py`. Port 9090 is confirmed listening inside the container and
`/metrics` returns live Prometheus data.

### Bug #2 — Missing Channel Event Wait (Medium) ✓

The `threading.Event` in `SSHServer` is set correctly in both
`check_channel_shell_request` and `check_channel_exec_request`. `_handle_client()`
waits on it before sending the welcome banner, preventing the race where the banner
arrived before the channel was ready.

### Bug #3 — Incorrect Initial cwd (Medium) ✓

`init_session_state()` confirmed to return `cwd: /root`. Root home directory is
correctly initialised in the virtual filesystem with all expected files.

### Bug #4 — Static Fail-Before-Accept Count (Medium) ✓

`SSHServer` now uses per-instance `self._fail_before_accept = random.randint(1, 3)`.
Verified during the exec_command test — the client saw "Permission denied" twice
before succeeding, consistent with the random range.

### Bug #5 — Fake Last Login Banner (Medium) ✓

`_fake_last_login()` generates realistic entries with timestamps 1–30 days in the
past and random RFC1918 source IPs. Sample outputs:

```
Last login: Wed Feb 25 22:14:57 2026 from 172.27.192.4
Last login: Sat Feb 07 07:27:18 2026 from 172.17.33.47
Last login: Fri Feb 20 04:46:43 2026 from 192.168.146.136
```

### Bug #6 — exec_command Not Routed Through Command Handler (Low) ✓

Non-interactive SSH commands now execute through the full `handle_command()` path.
Tested with:

```
ssh -p 2222 -o StrictHostKeyChecking=no root@localhost 'id'
```

Output: `uid=0(root) gid=0(root) groups=0(root)`

### Bug #7 — Static /proc/uptime and /proc/loadavg (Low) ✓

Dynamic values are computed per-session inside `init_session_state()` and stored
in the virtual filesystem. Sample values from a live session:

```
/proc/uptime:   6607975.00 12617016.57
/proc/loadavg:  0.26 0.05 0.14 1/275 1036
```

Note: the values are stored at `state["files"]["/proc/uptime"]` (not as top-level
state keys) — an early verification check was mis-targeted and gave a false
negative that was subsequently corrected.

### Bug #8 — history Command Not Implemented (Low) ✓

`handle_command('history', state)` returns a correctly formatted numbered list of
in-session commands:

```
  1  pwd
  2  whoami
  3  ls
  4  id
```

`tty_state.command_history` is accessible via `session_state["tty_state"]` and
correctly fed into the `history` builtin handler.

### Bug #9 — ls -l Block Count Incorrect (Low) ✓

Block counts in `ls -l` output are now computed from actual `FileMetadata.size`
values using 512-byte block rounding (`max(8, (size + 511) // 512)`).

### Bug #10 — Base64 Detection False Positive (Low) ✓

`_has_suspicious_encoding()` now correctly treats an invalid base64 decode
(`_binascii.Error`) as a non-match rather than flagging the string as suspicious.

### Bug #11 — Thread-Unsafe Config Singleton (Low) ✓

`get_config()` uses double-checked locking with `_config_lock` to prevent
concurrent construction of multiple `Config` instances.

## Session 2 — Test Fixes, Realism Improvements, Thread Safety

### Summary

Actioned the 7 recommendations identified at the end of Session 1: fixed all 6
pre-existing test failures, hardened one latent flaky test, improved honeypot
realism, closed a thread-safety gap, and improved the system prompt.

### 1. Fixed 6 pre-existing test failures (+ 1 newly discovered flaky test)

**`tests/test_command_handler.py` — EXIT_SENTINEL tests (2 fixes)**

Both `test_exit_returns_special_token` and `test_logout_returns_special_token` were
hardcoding the string `"__MIRAGEPOT_EXIT__"`, but `EXIT_SENTINEL` is now a
session-unique token (`"__exit_<16-hex-chars>__"`) generated at import time using
`secrets.token_hex(8)`. Fixed by importing `EXIT_SENTINEL` from `command_handler`
and asserting against it directly.

**`miragepot/filesystem.py` — `_under()` root path bug (1 production fix)**

`find / -type d` returned nothing. The `_under()` helper (added as P1.1-06 to fix
a string-prefix false-positive) constructed `start_path + "/"`, which becomes
`"//"` when `start_path == "/"`. No path starts with `"//"`, so all results were
excluded. Fixed with a special case: when `start_path == "/"`, return `True` for
every path. The P1.1-06 protection is preserved for all non-root searches.

**`tests/test_ssh_interface.py` — 3 auth tests + 1 flaky test (4 fixes)**

P2-04 (fail-before-accept) causes the server to reject the first 1–3 auth attempts
before accepting. Four tests assumed the first call would succeed:

- `test_check_auth_password_records_attempt` — rewritten to exhaust
  `server._fail_before_accept` failures then assert the next call succeeds.
- `test_get_auth_summary` — same pattern; `attempt_count` is now asserted as `n + 1`.
- `test_get_allowed_auths` — removed stale `"publickey" in allowed` assertion.
  P2-08 intentionally advertises only `"password"` to maximise credential capture.
- `test_multiple_auth_attempts` — discovered to be flaky (~25% failure rate when
  `_fail_before_accept == 3`). Rewritten to make exactly `n + 1` calls regardless
  of the random value.

### 2. Dynamic fallback responses (`miragepot/ai_interface.py`)

`_generate_fallback_response()` had a hardcoded static dict for `date`, `uptime`,
`w`, and `last`. These returned the same strings every session — a detectable
honeypot fingerprint. Added dynamic generation for all four:

- `date` — uses `datetime.now(timezone.utc)` with strftime formatting.
- `uptime` — random uptime of 15–120 days, random load averages, current system time.
- `w` — same dynamic uptime plus a user table row with random login time and random
  RFC1918 source IP.
- `last` — two recent login entries with random timestamps relative to now (0–2 and
  3–7 days ago), random IPs, and a reboot line 15–120 days ago.

### 3. `AI_REVELATION_PHRASES` overreach (`miragepot/response_validator.py`)

Removed 9 over-broad phrases that caused valid LLM responses to be silently dropped:

- `"the command"`, `"this command"` — appear in error messages and man pages
- `"the output"`, `"this output"` — appear in apt and tool output
- `"note that"` — ubiquitous in config files and documentation output
- `"here is"`, `"here's"`, `"here are"` — appear in `--help` text
- `"in reality"` — too generic

Kept the unambiguous phrases: `"please note"`, `"keep in mind"`, `"as you can see"`.

Updated `tests/test_response_validator.py`: split `test_explanatory_phrases` and
added `test_formerly_overbroad_phrases_now_pass` as a regression guard.

### 4. `reload_config()` thread safety (`miragepot/config.py`)

`reload_config()` was updating `_config` without holding `_config_lock`, creating
a race condition with concurrent callers and `get_config()`. Fixed by wrapping the
assignment in `with _config_lock:`, consistent with the double-checked locking
pattern already used in `get_config()`.

### 5. System prompt improvements (`data/system_prompt.txt`)

- **Dynamic PS examples** — added a note that PIDs and numeric fields must vary
  naturally between sessions.
- **Network commands** — added `netstat -tlnp` and `ss -tlnp` example output
  formats so the LLM knows exactly what to produce for network enumeration commands.
- **`cat` file handling** — clarified the distinction between files in vs. not in
  the session state `files` object. Previously ambiguous.
- **Session state context** — clarified that `cwd` is used for relative path
  resolution.

## Session 3 — Fix .env.docker.example Missing Password Fields

the dashboard password — `MIRAGEPOT_DASHBOARD_PASSWORD` was missing from the example
file entirely. `GRAFANA_ADMIN_PASSWORD` was present but had minimal comments that
didn't explain what to do.

### Changes

**`.env.docker.example`**

- Added `MIRAGEPOT_DASHBOARD_PASSWORD=changeme_set_a_strong_password_here` with a
  4-line comment block explaining it is required, why it matters, and how to generate
  a strong value (`openssl rand -base64 32`).
- Expanded `GRAFANA_ADMIN_PASSWORD` comment from 2 lines to 3 lines, matching the
  same style and `openssl` hint.

The example file now matches `.env.docker` line-for-line (264 lines), with
`changeme_set_a_strong_password_here` as the placeholder value instead of `1234`.

### Files Changed

- `.env.docker.example` — added `MIRAGEPOT_DASHBOARD_PASSWORD`, expanded Grafana password comments
