## Work Done

### 1. Fixed 6 pre-existing test failures (+ 1 newly discovered flaky test)

**`tests/test_command_handler.py` — EXIT_SENTINEL tests (2 fixes)**

Both `test_exit_returns_special_token` and `test_logout_returns_special_token` were hardcoding the string `"__MIRAGEPOT_EXIT__"`, but `EXIT_SENTINEL` is now a session-unique token (`"__exit_<16-hex-chars>__"`) generated at import time using `secrets.token_hex(8)`. Fixed by importing `EXIT_SENTINEL` from `command_handler` and asserting against it directly.

**`miragepot/filesystem.py` — `_under()` root path bug (1 production fix)**

`find / -type d` returned nothing. The `_under()` helper (added as P1.1-06 to fix a string-prefix false-positive) constructed `start_path + "/"`, which becomes `"//"` when `start_path == "/"`. No path starts with `"//"`, so all results were excluded. Fixed with a special case: when `start_path == "/"`, return `True` for every path (everything is under root). The P1.1-06 protection is preserved for all non-root searches.

**`tests/test_ssh_interface.py` — 3 auth tests + 1 flaky test (4 fixes)**

P2-04 (fail-before-accept) causes the server to reject the first 1–3 auth attempts before accepting. Four tests assumed the first call would succeed:

- `test_check_auth_password_records_attempt` — rewritten to exhaust `server._fail_before_accept` failures then assert the next call succeeds.
- `test_get_auth_summary` — same pattern; `attempt_count` is now asserted as `n + 1`.
- `test_get_allowed_auths` — removed stale `"publickey" in allowed` assertion. P2-08 intentionally advertises only `"password"` to maximise credential capture.
- `test_multiple_auth_attempts` — discovered to be flaky (~25% failure rate when `_fail_before_accept == 3`). Rewritten to make exactly `n + 1` calls regardless of the random value.

### 2. Dynamic fallback responses (`miragepot/ai_interface.py`)

`_generate_fallback_response()` had a hardcoded static dict for `date`, `uptime`, `w`, and `last`. These returned the same strings every session — a detectable honeypot fingerprint.

Added dynamic generation for all four:
- `date` — uses `datetime.now(timezone.utc)` with strftime formatting.
- `uptime` — random uptime of 15–120 days, random load averages, current system time.
- `w` — same dynamic uptime plus a user table row with random login time and random RFC1918 source IP.
- `last` — two recent login entries with random timestamps relative to now (0–2 and 3–7 days ago), random IPs, and a reboot line 15–120 days ago.

### 3. `AI_REVELATION_PHRASES` overreach (`miragepot/response_validator.py`)

Removed 9 over-broad phrases from `AI_REVELATION_PHRASES` that caused valid LLM responses to be silently dropped:

- `"the command"`, `"this command"` — appear in error messages and man pages
- `"the output"`, `"this output"` — appear in apt and tool output
- `"note that"` — ubiquitous in config files and documentation output
- `"here is"`, `"here's"`, `"here are"` — appear in `--help` text
- `"in reality"` — too generic

Kept the unambiguous phrases: `"please note"`, `"keep in mind"`, `"as you can see"`.

Updated `tests/test_response_validator.py` accordingly: split `test_explanatory_phrases` into two tests — one for phrases that should still be detected, and a new `test_formerly_overbroad_phrases_now_pass` that verifies the removed phrases no longer cause false positives.

### 4. `reload_config()` thread safety (`miragepot/config.py`)

`reload_config()` was updating `_config` without holding `_config_lock`, creating a race condition with concurrent callers and `get_config()`. Fixed by wrapping the assignment in `with _config_lock:`, consistent with the double-checked locking pattern already used in `get_config()`.

### 5. System prompt improvements (`data/system_prompt.txt`)

Four improvements:
- **Dynamic PS examples** — added a note that PIDs and numeric fields must vary naturally between sessions; removed the implication that the same fixed PIDs should be used every time.
- **Network commands** — added `netstat -tlnp` and `ss -tlnp` example output formats so the LLM knows exactly what to produce for network enumeration commands.
- **`cat` file handling** — clarified the distinction between "file in session state `files` object → output its content" vs. "file not in session state → No such file or directory". Previously the prompt was ambiguous.
- **Session state context** — clarified that the `cwd` field is used for relative path resolution.
