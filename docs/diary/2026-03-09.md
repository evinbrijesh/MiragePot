## Session 1 — Closing the March 5 Bug Tracker (BUG-01 through BUG-10)

Worked through all 10 open items from `docs/security/security-2026-03-05.md`.

### BUG-01 — Ed25519/ECDSA Key Generation Crash (Critical)

**File:** `miragepot/ssh_interface.py`

The P2-07 fix from March 5 generated Ed25519/ECDSA keys using the `cryptography`
library, wrapped them via `paramiko.Ed25519Key.from_private_key()`, then called
`.write_private_key_file()` on the result. Paramiko does not implement this method
on keys loaded via `from_private_key()` — the call falls through to the `PKey` base
stub which raises `Exception("Not implemented in PKey")`.

**Fix:** Separated generation from saving. Keys are now generated with the
`cryptography` library, serialised to OpenSSH PEM format with `private_bytes()`,
written directly to disk via `path.write_bytes()` + `path.chmod(0o600)`, then loaded
back with `from_private_key_file()`. The generate-and-save helpers were renamed to
`_generate_and_save_ed25519_key(path)` and `_generate_and_save_ecdsa_key(path)`.

### BUG-02 — Race Condition in Metrics Singleton (High)

**File:** `miragepot/metrics.py`

The double-checked locking pattern had an unprotected outer `if cls._instance is None`
check before acquiring the lock. Two threads could both pass this check simultaneously,
potentially constructing two separate `MetricsCollector` instances.

**Fix:** Removed the outer unprotected check; always acquire the lock first.

### BUG-03 — Unbounded Credential Storage (High)

**File:** `miragepot/metrics.py`

`log_credential_attempt()` appended every unique `username:password` pair to a plain
`set` with no cap on the set itself. The Prometheus gauge was capped at 1,000 for
metric purposes, but the underlying set grew without limit.

**Fix:** Added a hard cap of 10,000 entries on the set itself. Added truncation of
`username` and `password` to 256 characters before storing.

### BUG-04 — Find Command Path Prefix Collision (High)

**File:** `miragepot/filesystem.py`

The virtual `find` implementation used a raw `startswith()` check, so
`find /home/user` incorrectly matched paths beginning with `/home/username`.
The `_under()` helper from P1.1-06 already handles this correctly for other
commands but `find` was not using it.

**Fix:** Replaced the raw `startswith` check with `_under()`.

### BUG-05 — UTF-8 Filtering Breaks International Input (High)

**File:** `miragepot/tty_handler.py`

The P5-07 byte-filter (`bytes(b for b in data if b < 128)`) destroyed valid UTF-8
multi-byte sequences. Every byte of a non-ASCII UTF-8 character has the high bit
set, silently erasing Chinese, Arabic, Russian, Japanese, emoji, and any other
non-Latin input.

**Fix:** Replaced the byte-range filter with a decode-re-encode pass:
`data.decode('utf-8', errors='replace').encode('utf-8')`, falling back to the
old filter only on unexpected exceptions.

### BUG-06 — Incomplete Filename Sanitisation (High)

**File:** `miragepot/ai_interface.py`

`_sanitize_filename()` blocked known-dangerous characters but missed zero-width
spaces (U+200B/C/D), right-to-left override (U+202E), and byte order mark (U+FEFF).

**Fix:** Added a pre-pass using `unicodedata.category()` to strip all Unicode
format/control characters (categories `Cf`, `Cc`, `Cs`, `Co`).

### BUG-07 — File Descriptor Double-Close / Silent fsync Skip (Medium)

**File:** `miragepot/server.py`

`_write_config_atomic()` wrapped the temp fd in `os.fdopen()`, which takes ownership
and closes it when the `with` block exits. The code then called `os.fsync(tmp_fd)`
and `os.close(tmp_fd)` on the already-closed fd. The outer `try/except` swallowed
the resulting `OSError`, silently skipping the fsync.

**Fix:** Moved `f.flush()` + `os.fsync(f.fileno())` inside the `with os.fdopen()`
block before the context manager closes the fd. Removed the redundant `os.close()`
from `finally`.

### BUG-08 — Mixed-Script Detection False Positives (Medium)

**File:** `miragepot/command_handler.py`

The mixed-script Unicode detection flagged any command containing characters from
more than 2 Unicode scripts. The threshold was too low — legitimate commands like
`git commit -m 'Fix: 修复错误'` or `curl https://例.jp/file_résumé.pdf` exceed it.

**Fix:** Raised the threshold from `> 2` to `>= 3` distinct non-Latin scripts, which
was the original intent documented in the audit finding.

### BUG-09 — Rate Limiter Cleanup Race (Medium)

**File:** `miragepot/rate_limiter.py`

`_cleanup_old_connections()` built the list of IPs to remove by iterating
`self._connections` without holding the lock, then acquired the lock to delete them.
In the window between building the list and acquiring the lock, a fresh connection
from one of the listed IPs could be added and then immediately deleted.

**Fix:** Moved the iteration inside the lock so the full collect-and-delete operation
is atomic.

### BUG-10 — Inconsistent Timestamp Parsing (Low)

**File:** `dashboard/app.py`

`parse_timestamp()` used bare `except:` clauses catching `KeyboardInterrupt` and
`SystemExit`. The three fallback formats produced datetimes with inconsistent
timezone awareness, causing potential `TypeError` crashes when comparing them.

**Fix:** Replaced bare `except:` with `except (ValueError, TypeError, OSError):`.
Added `.replace(tzinfo=timezone.utc)` normalisation whenever `tzinfo is None`.

### Key Implementation Notes

- `server.py` has two server paths — the standalone `start_server()` function and
  the `HoneypotServer` class. C1, C4, H1, and H7 needed to be applied to both.
- The H4 fix went through two iterations. The first attempt to use `re.search`
  everywhere was wrong because plain shell patterns like `"chmod +x"` are valid
  regex where `+` is a quantifier. The final fix uses `re.search` only when the
  pattern contains explicit metacharacters (`.*`, `|`, `[`).
- The H5 fix also went through two iterations. The first pass over-narrowed
  `AI_REVELATION_PHRASES` and broke `test_helpful_assistant_phrases` and
  `test_explanatory_phrases`. The final fix identifies and restores exactly the
  phrases asserted by those tests.
- LSP errors for `"ollama" is possibly unbound` in `ai_interface.py` are
  pre-existing — caused by the conditional `try: import ollama` at the top of the
  file — and are not actionable.
