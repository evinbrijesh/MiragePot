# MiragePot Report Pack

This folder contains the documentation set that maps cleanly to an academic/technical project report.

Suggested report structure (and where to pull content from):

- Abstract / Executive Summary: `docs/info/MVP.md`
- Problem Statement + Motivation: `docs/info/PRD.md`
- Objectives + Scope: `docs/info/MVP.md`, `docs/info/PRD.md`
- System Design / Architecture: `docs/info/architecture.md`, `docs/info/HOW_IT_WORKS.md`
- Implementation Details: `docs/info/TECHNICAL_REFERENCE.md`, `docs/info/INTERNALS.md`, `docs/info/API_AND_CODE_REFERENCE.md`
- Deployment + Operations: `docs/INSTALL.md`, `docs/USAGE.md`, `docs/info/DOCKER_DEPLOYMENT.md`, `docs/OFFLINE_DEPLOYMENT.md`, `docs/TROUBLESHOOTING.md`
- Monitoring + Observability: `docs/info/MONITORING.md`
- Notifications / Alerting (if included in your report): `docs/info/NOTIFICATIONS.md`
- Demo / Presentation Script: `docs/info/DEMO_WALKTHROUGH.md`
- Research Methodology: `docs/info/RESEARCH_METHODOLOGY.md`
- Evaluation Results Template: `docs/info/EVALUATION_RESULTS_TEMPLATE.md`
- Threats to Validity: `docs/info/THREATS_TO_VALIDITY.md`
- Reproducibility Checklist: `docs/info/REPRODUCIBILITY_CHECKLIST.md`
- Future Work: `docs/info/FUTURE_UPDATES.md`

If you only share one docs entrypoint for report writing, share this file.

Quick pointers:

- Practical entrypoint: `docs/info/COMPLETE_GUIDE.md`
- System overview: `docs/info/HOW_IT_WORKS.md`
